# Probe: tiling a 300 MB Image

**Question:** can the build tile a 300 MB Image with libvips, and does the output fit
GitHub Pages?

**Measured locally, 2026-10-04** (not yet on a GitHub runner):

| Input | Time | Peak memory | Output |
|---|---|---|---|
| 10000 x 10000 RGB TIFF, uncompressed, 286 MiB | 1.9 s | 144 MB | 540 files, 70 MB |

The input was Gaussian noise, which JPEG compresses worst, so 70 MB is an upper bound
for this pixel count. At that rate Pages' 1 GB holds about 14 such Images.

**Finding that changes the plan:** `sharp` (0.35) bundles libvips and writes IIIF
Image API 3 level-0 tiles itself: `sharp(src).tile({ layout: 'iiif3', size: 512 })`.
The Action needs no `apt-get install libvips-tools`. ADR-0003 still holds: it is
libvips, in the Action, not in the browser.

**Finding about `info.json`:** libvips writes an absolute `id` (the `id` option plus
the folder name). The viewer must not trust it: it fetches `info.json` itself and sets
`id` to the URL it fetched from, so a Collection works on any host and in local preview.

**Still open:** the same run on `ubuntu-latest`, including the Release download and
the Pages deploy. That needs a scratch repository on GitHub.
